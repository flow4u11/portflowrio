# Portfolio design references

Reviewed 7 October 2026. Recommendations below adapt the references to the requested spacious white hero; timings and dimensions are proposed for this portfolio, not copied requirements. No component code or dependencies were installed. No `AGENTS.md` was found in the workspace or its parent directories.

1. **Keep a single centered hero composition.** Use a circular portrait, Chayathorn Chianpolsane, a muted “UX/UI Designer” line, and one rounded Explore link. Reserve a generous empty margin above and below. A single 500–650 ms entrance with opacity and at most 12 px upward travel can introduce the portrait, title, and link in a short sequence. The [21st hero collection](https://21st.dev/community/components/s/hero) documents centered headline layouts; its [Centered Hero with Image Fan](https://21st.dev/@felipemenezes098/components/hero-10) is a composition reference. Adapt the centered alignment to the requested single portrait.

2. **Give Explore a small, purposeful response.** Use a near-black pill in light mode, a soft neutral pill in dark mode, and a trailing arrow. On hover or keyboard focus, move only the arrow 3 px over 160–200 ms. Use an ordinary anchor to Selected Work, with a visible focus outline. Smooth scrolling should become immediate under reduced motion. The [21st button collection](https://21st.dev/community/components/s/button) supports neutral bases and animated hover treatments.

3. **Let project imagery supply the color.** Use a consistent two-column media-card grid on desktop and one column on mobile. Place the project title, discipline, and short outcome below each image. A 1.02 image scale and slightly darker border on hover can signal an opening action; expose the same outline for keyboard focus. The [21st card collection](https://21st.dev/community/components/s/card) recommends media cards for image-led content and consistent grid spacing. The [GSAP Showcase](https://gsap.com/showcase/) links [Huy Phan’s portfolio](https://huyml.co/), whose Selected Work structure is a useful content-order reference.

4. **Reveal sections once while preserving normal scrolling.** Introduce section labels and project rows with a 400–550 ms opacity reveal and no more than 16 px travel. Keep delays below 80 ms between neighboring cards. Avoid tying reading position to pinned animation sequences. The [GSAP Showcase](https://gsap.com/showcase/) provides motion inspiration; [GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/) documents responsive animation setup and reduced-motion adaptation. The exact reveal treatment here is our recommendation.

5. **Make the top-right theme switch quiet and explicit.** Use visible Light/Dark labels with a small sun or moon icon, a 44 px minimum target, an accessible current state, and a persisted preference. A 150–200 ms background/text-color transition is enough. [Animate UI’s Theme Toggler](https://animate-ui.com/docs/components/buttons/theme-toggler) is a relevant control reference; its gradual transition can be simplified for this minimal layout.

6. **Use restrained content transitions in case studies.** For optional Research / Design / Outcome panels, use an understated active underline and a quick opacity change. Keep project summaries visible before opening panels, so the work remains easy to scan. [Animate UI Tabs](https://animate-ui.com/docs/components/animate/tabs) illustrates layered panels; its transition API supports a spring with zero bounce. Native buttons, keyboard navigation, and clearly associated panels remain necessary if implementing tabs independently.

**Motion accessibility:** respect `prefers-reduced-motion` across the entire page. Remove translation, scaling, automatic scrolling, and continuous background movement; show all content immediately. Retain simple color state changes if useful. [Animate UI accessibility guidance](https://animate-ui.com/docs/accessibility) recommends `MotionConfig reducedMotion="user"` when using its Motion-based components. [GSAP matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/) supports equivalent media-query conditions. CSS media queries are sufficient for a lightweight implementation without either library.
